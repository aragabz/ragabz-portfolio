Compose on the desktop is no longer a novelty — it's a shipping target in 2026.

<Callout variant="tip" title="What you'll learn">
- How to structure `expect/actual` for file system, process, and clipboard access

### Project structure for multi‑platform desktop

```text
my-app/
├─ composeApp/
│  ├─ src/
│  │  ├─ commonMain/      # Shared Compose UI, business logic
│  │  ├─ androidMain/     # Android entry point + actuals
│  │  ├─ iosMain/         # iOS entry point + actuals (via CMP)
│  │  └─ jvmMain/         # Desktop entry point (main.kt) + actuals — minimal
│  └─ build.gradle.kts    # Targets, dependencies & desktop packaging
└─ iosApp/                # Xcode project wrapping the shared UI
```

### Desktop entry point (jvmMain) and shared UI (commonMain)

```kotlin
// jvmMain/kotlin/main.kt — the same JVM entry point runs on all three OSes
fun main() = application {
    Window(onCloseRequest = ::exitApplication, title = "My App") {
        MaterialTheme {
            App()
        }
    }
}

// commonMain
@Composable
fun App() {
    // Example: a file‑picker button that works on all desktops
    var path by remember { mutableStateOf<String?>(null) }
    Column(verticalArrangement = Arrangement.Center, horizontalAlignment = Alignment.CenterHorizontally) {
        Button(onClick = {
            // pickFile is declared as `expect` in commonMain (see below)
            path = pickFile(
                title = "Pick a file",
                initialDirectory = systemPaths().documents,
                extensions = listOf("txt", "md"),
            )
        }) {
            Text("Select a file")
        }
        Text("Chosen: ${path ?: "—"}")
    }
}
```

### `expect/actual` for desktop‑specific APIs

**CommonMain — expect declarations**

```kotlin
expect fun pickFile(title: String, initialDirectory: String, extensions: List<String>): String?
expect fun systemPaths(): SystemPaths
expect fun readClipboardText(): String?

data class SystemPaths(
    val documents: String,
    val downloads: String,
)
```

**Actual implementations** (each platform source set):

**Desktop (JVM — Linux, macOS, Windows)**

```kotlin
// jvmMain
actual fun systemPaths(): SystemPaths {
    val home = System.getProperty("user.home")
    return SystemPaths(documents = "$home/Documents", downloads = "$home/Downloads")
}

actual fun readClipboardText(): String? {
    // java.awt.Toolkit gives cross‑platform clipboard access
    val clipboard = java.awt.Toolkit.getDefaultToolkit().systemClipboard
    return if (clipboard.isDataFlavorAvailable(DataFlavor.stringFlavor)) {
        clipboard.getData(DataFlavor.stringFlavor) as? String
    } else null
}

actual fun pickFile(title: String, initialDirectory: String, extensions: List<String>): String? {
    val dialog = FileDialog(null as Frame?, title, FileDialog.LOAD).apply {
        directory = initialDirectory
        // Note: the AWT filename filter is ignored by the native Windows dialog
        setFilenameFilter { _, name -> extensions.any { name.endsWith(".$it") } }
        isVisible = true // blocks until the user picks a file or cancels
    }
    return dialog.file?.let { File(dialog.directory, it).absolutePath }
}
```

**macOS‑specific APIs**  
The JVM desktop target is a single source set for all three OSes, so there’s no separate macOS `actual`. If you need Cocoa APIs (e.g., `NSWorkspace`), branch at runtime on `System.getProperty("os.name")` and call native code via JNA/JNI — but the pure Java/AWT approach works on all three platforms without extra native code.

**Windows** — the same actuals work; just build with JDK 17+, which desktop packaging (`jpackage`) requires.

### AWT / Swing interop

If you need existing desktop UI code, Compose can embed native components:

```kotlin
@Composable
fun SwingDemo() {
    // Embed a Swing button inside the Compose hierarchy
    SwingPanel(
        modifier = Modifier.size(200.dp, 48.dp),
        factory = { javax.swing.JButton("Swing says hi") },
    )
}
```

The reverse direction — hosting Compose inside an existing Swing app — uses `ComposePanel`.

In practice, most apps either:

- **Write desktop‑specific code in `expect/actual`** (file I/O, dialogs, system paths) as shown above.
- **Keep the UI 100 % Compose** and avoid legacy toolkits, since Compose’s own layout & theming usually suffices for greenfield desktop apps.

### Publishing to Windows/macOS/Linux from a single Gradle configuration

```kotlin
// composeApp/build.gradle.kts
import org.jetbrains.compose.desktop.application.dsl.TargetFormat

plugins {
    kotlin("multiplatform")
    id("org.jetbrains.compose")
    id("org.jetbrains.kotlin.plugin.compose")
}

kotlin {
    jvm()
    jvmToolchain(21)
    sourceSets {
        commonMain.dependencies {
            implementation(compose.material3)
            // Versions come from the Compose Multiplatform Gradle plugin
        }
        jvmMain.dependencies {
            implementation(compose.desktop.currentOs)
        }
    }
}

compose.desktop {
    application {
        mainClass = "MainKt"
        nativeDistributions {
            targetFormats(TargetFormat.Dmg, TargetFormat.Msi, TargetFormat.Deb)
            packageName = "MyApp"
            packageVersion = "1.0.0"
        }
    }
}
```

Running `./gradlew :composeApp:run` launches the desktop process on your dev machine. To produce native installers:

```bash
./gradlew :composeApp:createDistributable   # app image with a bundled JRE
./gradlew :composeApp:packageDistributionForCurrentOS
# Or a specific format — each must be built on its own OS (jpackage can't cross-compile):
./gradlew :composeApp:packageDmg   # macOS
./gradlew :composeApp:packageMsi   # Windows
./gradlew :composeApp:packageDeb   # Linux
```

### Common gotchas

| Gotcha | Fix |
|--------|-----|
| `HeadlessException` in CI | AWT dialogs and desktop UI tests need a display; on Linux CI runners wrap the Gradle command in `xvfb-run`. |
| Clipboard not working on Wayland (Linux) | `java.awt.Toolkit.getDefaultToolkit().getSystemClipboard()` works on X11, Windows, and macOS; on Wayland you may need a small native bridge. |
| Different JDK versions per OS | Use `jvmToolchain(21)` in the `kotlin {}` block to enforce a consistent JDK across all platforms. |
| `File.renameTo()` fails silently (it just returns `false`) | Use `java.nio.file.Files.move()`, which throws a descriptive exception; add `StandardCopyOption.ATOMIC_MOVE` when source and target are on the same file system. |
