The promise of Kotlin Multiplatform is one source of truth for your app's logic — here's how to make it work beyond a shared UI toolkit.

<Callout variant="tip" title="What you'll learn">
- How to set up a `commonMain` module with Koin for DI
- Writing a shared Ktor client that works on JVM, iOS, and WasmJS
- Serialization strategies: Kotlin Serialization vs. Moshi per platform
</Callout>

### Multi‑module project layout

```text
my-app/
├── commonMain/          # Shared Kotlin code (models, DI, networking)
├── androidApp/          # Android UI (Compose) + main {}
├── iosApp/              # Xcode project wrapping Compose UI
├── desktopApp/          # JVM desktop (optional)
└── webApp/              # WasmJS entry point
```

### Shared models & DI with Koin

```kotlin
// commonMain — data models
@Serializable
data class User(val id: Int, val name: String, val email: String)

// Koin module (commonMain)
import koin.android.ext.koinViewModel
import org.koin.dsl.module

val commonModule = module {
    single { User(0, "unknown", "") }
    viewModel { UserViewModel(get()) }
}

// UserViewModel in commonMain
class UserViewModel(private val repo: UserRepository) : ViewModel() {
    private val _uiState = MutableStateFlow UiState.Loading()
    val uiState: StateFlow<UiState> = _uiState.stateIn(
        scope = CoroutineScope(Dispatchers.Main),
        started = SharingStarted.WhileSubscribed(5000),
        initialValue = UiState.Loading(),
    )

    fun load() {
        viewModelScope.launch {
            val u = repo.getUser()
            _uiState.postValue(u)
        }
    }
}
```

Koin’s `single` works across all targets because it resolves at runtime via reflection — no code‑gen step required.

### Shared Ktor client

```kotlin
// commonMain — Ktor setup
val httpClient: HttpClient = HttpClient(CORS) {
    install(ContentNegotiation) {
        json(JsonSerializer) // Kotlin Serialization serializers
    }
    install(DefaultHeaders) { headers("Accept" to "application/json") }
}

// iOS / WasmJS expect the same artifact; no expect/actual needed for the client itself.
```

On iOS, Ktor is distributed as an framework — just add the same dependency version in `iosApp/build.gradle.kts` and the shared `commonMain` client works unchanged.

### Serialization per platform

```kotlin
// commonMain — expect/actual for serializers
expect class UserSerializer : KSerializer<User>
actual object UserSerializer : KSerializer<User> {
    override val descriptor = DescriptorSerializer.descriptor
    override fun serialize(serializing: SerializingBuffer, value: User) = ...
    override fun deserialize(deserializing: DeserializingBuffer): User = ...
}

// iOS actual implementation (generated by Kotlin Serialization plugin)
actual object UserSerializer : KSerializer<User> { ... }
```

The `expect/actual` pattern lets you keep the *interface* in `commonMain` while the *byte‑code* is provided per‑platform by the Kotlin Serialization plugin (installed in each module).

<Callout variant="warning">
On web (WasmJS), the serializer module must be manually registered in `jsSerialize` / `jsDeserialize` hooks; otherwise the app crashes on deserialization. Add `KotlinSerializer.Registry` to your `index.js` entry point.
</Callout>

### Testing the shared layer

```kotlin
// commonMain test
class UserRepositoryTest {
    @Test fun `load user from repo returns expected model`() = runTest {
        val repo = UserRepository(FakeDao(), FakeApi())
        repo.load()
        assertEquals(User(1, "Alice", "alice@test"), repo.uiState.value)
    }
}
```

Since the repo lives in `commonMain`, the same test suite runs on Android, iOS test targets, and CI pipelines — one source of truth for logic correctness.
