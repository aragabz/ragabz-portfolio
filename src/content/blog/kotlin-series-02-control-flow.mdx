## `if` Is an Expression

In Java, `if` is a statement — it performs an action but produces no value. In Kotlin, **`if` returns a value**, which eliminates the classic ternary-operator need:

```kotlin
val number = 7

// if as a statement (performing actions)
if (number > 5) {
    println("big")
} else {
    println("small")
}

// if as an expression (producing a value)
val parity = if (number % 2 == 0) "even" else "odd"
println(parity) // odd
```

With multiple branches, the last expression of each branch becomes the result:

```kotlin
val score = 85

val grade = if (score >= 90) {
    println("Excellent!")
    "A"
} else if (score >= 80) {
    "B"
} else {
    "C"
}
```

Because branches must all produce values of a compatible type, the compiler can verify exhaustiveness in ways statements cannot.

<Callout variant="note">
There is no ternary operator (`condition ? a : b`) in Kotlin — you don't miss it. `val x = if (cond) a else b` reads just as well.
</Callout>

## `when`: Kotlin's Supercharged `switch`

`when` matches a value against multiple branches. Unlike Java's `switch`, it:

- Requires no `break` (no fall-through)
- Can match arbitrary expressions, not just constants
- Works as an expression itself
- Supports type checks, range checks, and destructuring

### Classic form with subject

```kotlin
val httpStatus = 404

val message = when (httpStatus) {
    200 -> "OK"
    301, 302 -> "Redirect"
    in 400..499 -> "Client error"          // range match
    else -> "Unknown"
}
```

Multiple values on one line mean logical OR: `301, 302 -> ...`.

### Matching types

Branches can check the *type* of the subject, with automatic smart-casting afterwards (more on smart casts in the null safety post):

```kotlin
fun describe(value: Any): String = when (value) {
    is Int -> "Integer: $value"            // value smart-cast to Int
    is String -> "String of ${value.length} chars"
    is List<*> -> "List with ${value.size} items"
    else -> "Something else"
}
```

### Conditions inside branches

```kotlin
val temp = 23

fun feel(): String = when {
    temp < 10 -> "cold"
    temp in 10..25 -> "pleasant"
    else -> "hot"
}
```

This is `when` **without a subject** — each branch is a boolean condition evaluated top-down, like a chain of `else if`s that reads far better.

### Combining both worlds

```kotlin
sealed interface PaymentResult // more on sealed types in post #5

data class Approved(val id: String) : PaymentResult
data class Declined(val reason: String) : PaymentResult
object Pending : PaymentResult

fun render(result: PaymentResult): String = when (result) {
    is Approved -> "Payment ${result.id} approved"
    is Declined -> "Declined: ${result.reason}"
    Pending -> "Waiting..."
}
```

When the subject is a `sealed` type and every subclass is covered, the compiler enforces exhaustiveness — no `else` branch needed, and adding a new subclass later causes a compile error everywhere you forgot to handle it. This pattern is the backbone of idiomatic Kotlin domain modeling.

## Ranges and Progressions

Ranges are first-class objects, not syntactic sugar:

```kotlin
val numbers = 1..5        // inclusive: 1, 2, 3, 4, 5
val exclusive = 1 until 5 // excludes end: 1, 2, 3, 4
val countdown = 5 downTo 1
val evens = 0..20 step 2
val letters = 'a'..'e'
```

Useful checks:

```kotlin
val age = 27
if (age in 18..65) println("working age")

'x' !in 'a'..'z' // false — negated membership
```

Ranges are iterable collections under the hood (progressions), so they compose with everything we'll learn about collections in [post #6](/blog/kotlin-series-06-collections-generics).

## Loops

### `for` iterates over anything iterable

Kotlin has no classic C-style `for(i = 0; i < n; i++)`. Instead, `for` works with any object providing an iterator — arrays, collections, ranges, strings, even your own classes:

```kotlin
for (i in 1..3) print("$i ")           // 1 2 3

for ((index, item) in listOf("a", "b").withIndex()) {
    println("$index -> $item")         // built-in index/value pair
}

val map = mapOf("a" to 1, "b" to 2)
for ((key, value) in map) {            // destructuring Map entries
    println("$key = $value")
}
```

That `(index, item)` syntax is a **destructuring declaration** — we'll unpack it fully when we cover data classes in [post #5](/blog/kotlin-series-05-oop-data-classes).

### `while` and `do..while`

Exactly what you expect from C-family languages:

```kotlin
var attempts = 0
while (attempts < 3) {
    println("Attempt ${attempts + 1}")
    attempts++
}

do {
    println("runs at least once")
} while (false)
```

## `break`, `continue`, and Labels

Standard behavior, plus one Kotlin addition — **labels** let you jump out of nested loops directly:

```kotlin
outer@ for (i in 1..3) {
    for (j in 1..3) {
        if (i * j > 6) continue@outer   // skip to next i
        if (i == 3 && j == 2) break@outer
        print("($i,$j) ")
    }
}
```

Without labels you'd need flag variables or extract the inner loop into a function. Labels are rare in day-to-day code but worth knowing.

<Callout variant="tip">
A cleaner alternative to `break` in complex logic: wrap the loop in a local function and use `return`. We'll see how in the next post.
</Callout>

<Callout variant="note" title="Looking ahead">
Recent Kotlin versions keep improving `when`: **guard conditions** (`is Int -> if (it > 0) ...` style branch guards) arrived as an experimental language feature in Kotlin 2.1 and stabilized through 2.2–2.3. Data-flow-based exhaustiveness checking became stable in Kotlin 2.3. We'll cover this evolution in the version-diff posts at the end of the series.
</Callout>
