## JUnit 5, the Kotlin Way

Function names can contain spaces via backticks — tests become self-documenting specs:

```kotlin
import kotlin.test.*

class MoneyTest {

    @Test
    fun `two equal amounts are structurally equal`() {
        assertEquals(Money(100, "USD"), Money(100, "USD"))
    }

    @Test
    fun `adding money keeps currency`() {
        val sum = Money(100, "USD") + Money(50, "USD")
        assertEquals(150, sum.amount)
    }

    @Test
    fun `negative amounts are rejected`() {
        assertFailsWith<IllegalArgumentException> {
            Money(-5, "EUR")
        }
    }
}
```

Note `assertFailsWith<T>` — exceptions as types, no try/catch gymnastics. Data classes (post #5) make structural assertions trivial since equality comes for free.

### Parameterized tests

```kotlin
class FizzBuzzTest {
    @ParameterizedTest(name = "{0} -> {1}")
    @CsvSource(
        "3, Fizz",
        "5, Buzz",
        "15, FizzBuzz",
        "7, 7",
    )
    fun `fizzbuzz maps numbers correctly`(input: Int, expected: String) {
        assertEquals(expected, fizzBuzz(input))
    }
}
```

## Kotest: A Kotlin-Native Alternative

[Kotest](https://kotest.io) offers multiple testing *styles* plus its own assertion library:

```kotlin
class StackSpec : FunSpec({
    test("popping empty stack throws") {
        val stack = Stack<Int>()
        shouldThrowExactly<NoSuchElementException> { stack.pop() }
    }
})
```

Its standout feature is **property-based testing** — generate hundreds of random inputs and verify invariants:

```kotlin
checkAll(arb.int()) { n ->
    listOf(n).reversed().reversed() shouldBe listOf(n)
}
```

Great for catching edge cases your example-based tests never imagined (empty lists, zero, `Int.MIN_VALUE`...).

## Testing Coroutines: Virtual Time

Naively sleeping in async tests makes suites slow and flaky. `runTest` replaces real delays with **virtual time** — a 10-second `delay()` completes instantly while preserving ordering semantics:

```kotlin
class TickerTest {

    @Test
    fun `ticker emits three events then stops`() = runTest {
        val emissions = mutableListOf<Int>()

        val job = launch {
            tickerFlow().take(3).toList(emissions)     // flow with delay(100) inside
        }
        advanceTimeBy(350)                              // fast-forward virtual clock
        job.join()

        assertEquals(listOf(1, 2, 3), emissions)        // completed instantly!
    }
}
```

Key tools inside `runTest`:

| API | Purpose |
|-----|---------|
| `advanceTimeBy(ms)` | fast-forward the virtual clock |
| `runCurrent()` | execute tasks scheduled for "now" |
| `StandardTestDispatcher` | deterministic manual scheduling |
| `UnconfinedTestDispatcher` | eager execution for setup steps |

Real-world pattern: inject dispatchers (`Dispatchers.IO` etc.) through constructors so tests can swap them for `UnconfinedTestDispatcher`. Hardcoding `Dispatchers.x` deep in business logic is untestable design.

## Mocking with MockK

MockK is built *for* Kotlin — it understands final classes (no need for `open`), objects, extension functions, and suspend:

```kotlin
class OrderServiceTest {

    private val repository = mockk<OrderRepository>(relaxed = true)
    private val notifier = mockk<Notifier>()

    private val service = OrderService(repository, notifier)

    @Test
    fun `submitting order notifies customer`() = runTest {
        every { repository.save(any()) } returns Order(id = "#42", status = "NEW") andThenAnswer { arg ->
            (arg as Order).copy(id = "#43")
        }
        coEvery { notifier.notifyCustomer(any(), any()) } just runs   // co* for suspending

        service.submit(Order(id = "", items = listOf("tea")))

        coVerify(exactly = 1) { notifier.notifyCustomer("#42", any()) }
    }
}
```

Highlights:

- `relaxed = true` auto-stubs anything you didn't configure — great for dependencies whose behavior is irrelevant to the case under test
- `coEvery`/`coVerify` handle `suspend` functions
- `just runs` stubs Unit-returning suspend calls
- `verifySequence`, `confirmVerified`, capture slots (`slot<String>()`) cover advanced verification

Prefer hand-written fakes when they're simple — over-mocking couples tests to implementation details:

```kotlin
class InMemoryOrderRepository : OrderRepository {
    private val orders = mutableMapOf<String, Order>()
    override fun save(order: Order) { orders[order.id] = order }
    override fun findById(id: String): Order? = orders[id]
}
```

## The Capstone Checklist: Idiomatic Kotlin

Seven posts of material, distilled into habits. When reviewing code (yours or others'), check:

### Expressions & structure
1. ✅ **`val` by default**, `var` only with justification (post #1)
2. ✅ **Expressions over statements**: `if`/`when` returning values, single-expression functions (posts #2–3)
3. ✅ **`when` over `if` chains**; sealed hierarchies for closed sets of states (posts #2, #5)

### Safety
4. ✅ **No `!!`, minimal platform-type leakage**; nullability explicit at boundaries (`String?` in DTOs, normalized internally) (post #4)
5. ✅ **`require`/`check`/`error`** for precondition failures instead of bare exceptions:
   ```kotlin
   fun transfer(amount: Money) {
       require(amount.isPositive) { "Amount must be positive" }
   }
   ```

### Modeling
6. ✅ **Data classes for values, sealed interfaces for alternatives, enums for constants** (post #5)
7. ✅ **Immutable state updated via `copy()`** — thread-friendliness for free (post #5)

### Functions
8. ✅ **Extension functions keep utilities discoverable** (`"a,b".splitAndTrim()`) (post #3)
9. ✅ **Scope functions used sparingly and purposefully** — `apply` to build, `let` to transform/null-gate, `also` to peek (post #3)

### Collections & generics
10. ✅ **Read-only collection types in APIs** (`List<T>` params/returns, never `MutableList`) (post #6)
11. ✅ **Sequences for large/lazy pipelines**; eager lists otherwise (post #6)
12. ✅ **Variance correct on generic types**: producer `out`, consumer `in` (post #6)

### Concurrency
13. ✅ **Structured concurrency always** — no `GlobalScope` in app logic; parallel I/O via `async` inside `coroutineScope` (post #7)
14. ✅ **Injected dispatchers**, blocking calls confined to `Dispatchers.IO` (post #7)
15. ✅ **Cancellation-friendly loops** — suspension points or explicit `ensureActive()` (post #7)

<Callout variant="tip">
A useful litmus test: hand your file to a Java developer. If they can translate it line-by-line back to Java without losing meaning, you've written Java-in-Kotlin. Idiomatic Kotlin leans on expressions, immutability, and the type system so the *compiler* carries more of the correctness burden.
</Callout>
