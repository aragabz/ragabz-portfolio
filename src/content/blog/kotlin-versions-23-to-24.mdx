## First: How Kotlin Releases Work Now

Two independent tracks since 2023:

- **Language releases** (`2.3.0`, `2.4.0`) every ~6 months — may add/stabilize language features
- **Tooling releases** (`2.3.20`, `2.4.10`) between them — bugfixes, platform support, tooling; **never** change language semantics

Practical consequence: you can adopt `X.Y.20` maintenance releases fearlessly mid-quarter, while planning `X.(Y+1).0` upgrades deliberately.

## Kotlin 2.3 (December 2025): Consolidation

### Stabilized: nested type aliases & smarter `when` exhaustiveness

[Nested type aliases](/blog/kotlin-versions-21-to-22) graduated to stable. Bigger deal for correctness: **data-flow-based exhaustiveness checking** for `when` became stable — the compiler now understands guards and complex conditions when deciding whether your `when` covers all cases:

```kotlin
sealed interface Event {
    data class Click(val x: Int, val y: Int) : Event
    data object Refresh : Event
}

fun handle(e: Event) = when (e) {
    is Click if e.x >= 0 -> move(e)
    is Click -> clamp(e)          // compiler PROVES remaining clicks land here
    Refresh -> reload()
}                                  // exhaustive — no else required
```

### Enabled by default: explicit backing fields

Properties can now declare their storage explicitly — including a backing field of a *different type* than the exposed property:

```kotlin
import java.util.UUID

class Order {
    val id: String
        field: UUID = UUID.randomUUID()   // stores a UUID…
        get() = field.toString()           // …exposes a String
}
```

Before this, the workaround was a second private property (`private val _id`), doubling naming noise across millions of lines of Kotlin. The `field` keyword finally owns first-class storage. (Stable in 2.4.)

### Experimental: unused return value checker

A whole category of bugs — calling a function and silently discarding its result — becomes visible:

```kotlin
val errors = mutableListOf<String>()

errors.add("missing id")    // ⚠️ warning: return value unused
                            // add() returns Boolean — did you mean contains()?
val added = errors.add("x") // ✅ explicit
```

It's driven by annotations (stdlib functions like `add`, `checkNotNull`, builders are annotated) and rolls out gradually — exactly the safe way to introduce warnings that touch nearly every codebase.

### Standard library: time and identity

- **`kotlin.time.Clock` and `Instant`** stabilized — portable time tracking across platforms, ending the need for kotlinx-datetime shims in shared code
- **UUID API improved** (generation/parsing), later stabilized in 2.4

### Platform highlights

| Area | Change |
|------|--------|
| JVM | Java 25 bytecode support |
| Kotlin/Native | Up to **40% faster release builds**, C/Obj-C import reaches Beta |
| Swift export | Enums export as native Swift enums; variadic function support |
| Kotlin/Wasm | New exception-handling proposal on by default |

### The breaking-changes corner

Every era ends some paths: `-language-version=1.8` support ended (and 1.9 became JVM-only), the ancient `kotlin-android-extensions` plugin now hard-fails configuration, and Ant build support was removed. If any of these apply to you, they're the actual migration work — the rest is version bumps.

## Kotlin 2.3.20 (March 2026): Tooling Release With One Big Preview

**Name-based destructuring** arrived experimentally. Positional destructuring has always had a footgun ([post #5](/blog/kotlin-series-05-oop-data-classes)):

```kotlin
data class Money(val amount: Long, val currency: String)

val price = Money(amount = 99, currency = "EUR")
val (amount, currency) = price        // positional — order matters!

val (currency2, amount2) = price      // compiles fine. Silently swapped. 💥
```

Name-based destructuring binds components **by property name**, so reordering a data class can never silently corrupt call sites:

```kotlin
// experimental preview (2.3.20+) — syntax still evolving before stabilization
val [amount = amt, currency = cur] = price
// amt ← price.amount, cur ← price.currency — regardless of declaration order
```

Same release refined overload resolution for context parameters and simplified Maven project setup (auto-added stdlib dependency, automatic source-root registration).

## Kotlin 2.4 (June 2026): Current Stable

The headline: **context parameters and explicit backing fields are stable**. Two of the most-requested ergonomic features are now production-grade with full compatibility guarantees:

```kotlin
// Ambient dependencies without DI-framework ceremony — now guaranteed-stable:
context(clock: Clock, logger: Logger)
fun audit(event: String) {
    logger.log("${clock.now()} :: $event")
}
```

Also in 2.4:

| Area | Highlights |
|------|-----------|
| Stdlib | **UUID API stable**; sorted-order checks (`isSorted*`) |
| JVM | Java 26 support; annotations preserved in metadata by default |
| Kotlin/Native | **Swift packages as dependencies**; CMS garbage collector on by default |
| Kotlin/Wasm | Incremental compilation by default; WebAssembly **Component Model** support |
| Kotlin/JS | Value classes exportable; ES2015-level output |
| Build | Gradle 9.5 compatibility; Maven auto-aligns Java↔JVM targets |

The multiplatform story is quietly becoming the main event: Swift package integration and the Wasm Component Model position Kotlin as a first-class citizen beyond Android and server.

## Upgrading Today (Practical Guidance)

For a typical JVM/backend project on 2.0–2.2 moving to 2.4.x:

1. **Bump the plugin version**, rebuild, triage warnings first — deprecations removed in 2.3 (like pre-1.9 language levels) will announce themselves loudly.
2. **Delete obsolete workarounds**: `_field` companion properties → explicit backing fields; manual parameter threading → consider context parameters where it genuinely simplifies.
3. **Enable the unused-return checker** in CI before turning it on locally — cheap early wins.
4. **Android projects**: verify AGP compatibility matrix alongside; Compose compiler ships with Kotlin now, so one version bump covers both.
5. **Libraries**: compile against the *lowest* language version you promise to support; consumers on older compilers stay compatible thanks to binary-compatibility guarantees.
