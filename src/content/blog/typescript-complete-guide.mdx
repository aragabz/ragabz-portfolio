## Fundamentals

### Why TypeScript?

JavaScript is dynamically typed — variables can hold anything, and the interpreter figures it out at runtime. That flexibility speeds up prototyping but causes bugs that only appear in production:

```js
// JavaScript — crashes at runtime
const user = { name: "Ahmed", age: 30 };
console.log(user.nmae); // undefined — typo goes unnoticed
```

TypeScript catches these at **compile time**:

```ts
// TypeScript — error before you run
const user = { name: "Ahmed", age: 30 };
console.log(user.nmae);     // Error: Property 'nmae' does not exist
```

### Primitive types

```ts
let isActive: boolean = true;
let count: number = 42;
let name: string = "TypeScript";
let nothing: null = null;
let notDefined: undefined = undefined;
```

### Arrays and tuples

```ts
let tags: string[] = ["typescript", "react"];
let scores: Array<number> = [100, 95, 98];

// Tuple — fixed length, known types at each position
let userInfo: [string, number, boolean] = ["Ahmed", 30, true];
```

### Objects — type vs interface

```ts
// type alias
type User = { id: string; name: string; email: string; };

// interface
interface User { id: string; name: string; email: string; }
```

| Feature | `interface` | `type` |
|---------|-------------|--------|
| Extending | `extends` keyword | `&` intersection |
| Declaration merging | ✅ Yes | ❌ No |
| Union types | ❌ No | ✅ Yes |
| Primitive aliases | ❌ No | ✅ Yes |
| Tuple types | ❌ No | ✅ Yes |

<Callout variant="info">
**Rule of thumb**: Use `interface` for object types that might be extended. Use `type` for everything else (unions, primitives, tuples, complex mapped types).
</Callout>

### Type inference — TypeScript's superpower

You don't need to annotate everything. TypeScript infers types from context:

```ts
const message = "Hello";        // string
const count = 42;               // number
const user = { name: "A", age: 30 }; // { name: string; age: number }

function add(a: number, b: number) {
  return a + b;  // inferred as number
}
```

When you *do* need annotations: function parameters, recursive functions, complex object literals, and public API boundaries.

### Functions

```ts
// Required parameters
function greet(name: string, age: number): string { return `${name} is ${age}`; }

// Optional parameters (must come last)
function greet(name: string, age?: number): string { return age ? `${name} is ${age}` : `Hello ${name}`; }

// Default parameters
function greet(name: string, greeting = "Hello"): string { return `${greeting}, ${name}`; }

// Rest parameters
function sum(...numbers: number[]): number { return numbers.reduce((a, b) => a + b, 0); }

// Function type as variable
type MathOp = (a: number, b: number) => number;
const add: MathOp = (a, b) => a + b;
```

### Union and intersection types

**Unions** — "one of these":

```ts
type Status = "idle" | "loading" | "success" | "error";

function process(input: string | number) {
  if (typeof input === "string") return input.toUpperCase();
  return input.toFixed(2);
}
```

**Intersections** — "all of these":

```ts
interface HasName { name: string; }
interface HasAge { age: number; }
type Person = HasName & HasAge;
const user: Person = { name: "Ahmed", age: 30 };
```

### Narrowing — proving types at runtime

```ts
function format(value: string | number | Date) {
  if (typeof value === "string") return value.toUpperCase();
  if (typeof value === "number") return value.toLocaleString();
  if (value instanceof Date) return value.toISOString();
  const exhaustive: never = value;  // exhaustive check
  return exhaustive;
}
```

### Literal types

```ts
type Direction = "north" | "south" | "east" | "west";
type HttpMethod = "GET" | "POST" | "PUT" | "DELETE" | "PATCH";
```

### Practical example: typed API response

```ts
interface ApiResponse<T> {
  data: T;
  meta: { timestamp: string; requestId: string; };
  success: boolean;
}

async function fetchUser(id: string): Promise<ApiResponse<User>> {
  const res = await fetch(`/api/users/${id}`);
  return res.json();
}
```

## Advanced Types

### Generics — write once, type safely everywhere

```ts
// Without generics — lose type info
function firstElement(arr: any[]): any { return arr[0]; }

// With generics — preserve type info
function firstElement<T>(arr: T[]): T | undefined { return arr[0]; }
const n = firstElement([1, 2, 3]);     // n is number ✅
const s = firstElement(["a", "b"]);    // s is string ✅
```

**Read `<T>` as "for some type T provided by the caller."**

**Constraints:**

```ts
interface HasLength { length: number; }

function logLength<T extends HasLength>(value: T): void {
  console.log(value.length);
}

logLength("hello");        // OK
logLength([1, 2, 3]);      // OK
// logLength(42);          // Error: number has no length
```

**Generic classes:**

```ts
class DataStore<T> {
  private items: T[] = [];
  add(item: T): void { this.items.push(item); }
  find(predicate: (item: T) => boolean): T | undefined { return this.items.find(predicate); }
}
```

**Generic factory functions:**

```ts
function createStateManager<T>(initial: T) {
  let state = initial;
  return {
    getState: () => state,
    setState: (newState: T | ((prev: T) => T)) => {
      state = typeof newState === "function" ? (newState as (prev: T) => T)(state) : newState;
    }
  };
}
```

### Conditional types — type-level if/else

```ts
type IsString<T> = T extends string ? true : false;
type A = IsString<string>;  // true
type B = IsString<number>;  // false
type C = IsString<string | number>; // true | false (distributed!)
```

### Infer — extract types from patterns

```ts
type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never;
type ElementType<T> = T extends (infer U)[] ? U : never;
type Awaited<T> = T extends Promise<infer U> ? U : T;
```

### Mapped types — transform object shapes

```ts
type MakeOptional<T> = { [K in keyof T]?: T[K]; };
type PartialUser = MakeOptional<User>;
```

**Built-in utility types:**

```ts
type PartialUser = Partial<User>;           // all optional
type RequiredUser = Required<PartialUser>;  // all required
type PublicUser = Pick<User, "id" | "name" | "email">;
type SafeUser = Omit<User, "password">;
type UserRoles = Record<"admin" | "user" | "guest", string[]>;
```

### Template literal types — string manipulation at type level

```ts
type EventName<T extends string> = `on${Capitalize<T>}`;
type ClickEvent = EventName<"click">;     // "onClick"
type Actions = "create" | "read" | "update" | "delete";
type ActionEvents = EventName<Actions>;   // "onCreate" | "onRead" | "onUpdate" | "onDelete"
```

### Real-world pattern: type-safe event emitter

```ts
type EventMap = {
  login: { user: User };
  logout: void;
  error: { message: string; code: number };
};

class EventEmitter<E extends Record<string, any>> {
  private listeners: { [K in keyof E]?: ((payload: E[K]) => void)[] } = {};

  on<K extends keyof E>(event: K, listener: (payload: E[K]) => void): void {
    (this.listeners[event] ??= []).push(listener);
  }

  emit<K extends keyof E>(event: K, payload: E[K]): void {
    this.listeners[event]?.forEach(l => l(payload));
  }
}

const events = new EventEmitter<EventMap>();
events.on("login", ({ user }) => console.log(user.name));    // ✅ typed
events.emit("login", { user: { id: "1", name: "Ahmed", email: "a@b.com" } });
```

## TypeScript with React & React Native

### Component props — the foundation

```tsx
interface ButtonProps {
  label: string;
  onPress: () => void;
  variant?: "primary" | "secondary" | "outline";
  disabled?: boolean;
}

function Button({ label, onPress, variant = "primary", disabled = false }: ButtonProps) {
  return (
    <TouchableOpacity onPress={onPress} disabled={disabled}>
      <Text style={styles[variant]}>{label}</Text>
    </TouchableOpacity>
  );
}
```

### Generic component props

```tsx
interface ListProps<T> {
  data: T[];
  renderItem: (item: T, index: number) => React.ReactNode;
  keyExtractor: (item: T) => string;
}

function List<T>({ data, renderItem, keyExtractor }: ListProps<T>) {
  return <FlatList data={data} renderItem={({ item, index }) => renderItem(item, index)} keyExtractor={keyExtractor} />;
}

// Usage — fully typed!
<List
  data={users}
  keyExtractor={u => u.id}
  renderItem={(user) => <Text>{user.name}</Text>}
/>
```

### Typing hooks — custom hooks with inference

```tsx
function useLocalStorage<T>(key: string, initialValue: T): [T, (value: T | ((prev: T) => T)) => void] {
  const [storedValue, setStoredValue] = useState<T>(() => {
    if (typeof window === "undefined") return initialValue;
    try {
      const item = window.localStorage.getItem(key);
      return item ? JSON.parse(item) : initialValue;
    } catch { return initialValue; }
  });

  const setValue = useCallback((value: T | ((prev: T) => T)) => {
    const valueToStore = value instanceof Function ? value(storedValue) : value;
    setStoredValue(valueToStore);
    window.localStorage.setItem(key, JSON.stringify(valueToStore));
  }, [key, storedValue]);

  return [storedValue, setValue];
}

// Usage — T inferred from initialValue
const [name, setName] = useLocalStorage("name", "Ahmed");        // string
const [count, setCount] = useLocalStorage("count", 0);            // number
```

### Async data hook with discriminated union

```tsx
type AsyncState<T> =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; data: T }
  | { status: "error"; error: Error };

function useAsync<T>(asyncFn: () => Promise<T>): AsyncState<T> {
  const [state, setState] = useState<AsyncState<T>>({ status: "idle" });

  useEffect(() => {
    let mounted = true;
    setState({ status: "loading" });
    asyncFn()
      .then(data => mounted && setState({ status: "success", data }))
      .catch(error => mounted && setState({ status: "error", error }));
    return () => { mounted = false; };
  }, [asyncFn]);

  return state;
}

// Usage — exhaustive switch on status
function UserProfile({ userId }: { userId: string }) {
  const state = useAsync(() => fetchUser(userId));
  switch (state.status) {
    case "idle": return null;
    case "loading": return <Spinner />;
    case "success": return <UserCard user={state.data} />;
    case "error": return <ErrorMessage error={state.error} />;
  }
}
```

### Forms — type-safe form handling

```tsx
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { z } from "zod";

const schema = z.object({
  email: z.string().email("Invalid email"),
  password: z.string().min(8, "Min 8 characters"),
  confirmPassword: z.string(),
}).refine(data => data.password === data.confirmPassword, {
  message: "Passwords don't match",
  path: ["confirmPassword"],
});

type FormData = z.infer<typeof schema>;

function RegisterForm() {
  const { register, handleSubmit, formState: { errors } } = useForm<FormData>({
    resolver: zodResolver(schema),
  });

  const onSubmit = (data: FormData) => console.log(data); // Fully typed!

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register("email")} placeholder="Email" />
      {errors.email && <span>{errors.email.message}</span>}
      <input {...register("password")} type="password" />
      {errors.password && <span>{errors.password.message}</span>}
      <button type="submit">Register</button>
    </form>
  );
}
```

### Context — typed global state

```tsx
interface ThemeContextValue { theme: "light" | "dark"; toggleTheme: () => void; }

const ThemeContext = createContext<ThemeContextValue | null>(null);

function ThemeProvider({ children }: { children: React.ReactNode }) {
  const [theme, setTheme] = useState<"light" | "dark">("light");
  const toggleTheme = useCallback(() => setTheme(t => t === "light" ? "dark" : "light"), []);

  return <ThemeContext.Provider value={{ theme, toggleTheme }}>{children}</ThemeContext.Provider>;
}

function useTheme(): ThemeContextValue {
  const context = useContext(ThemeContext);
  if (!context) throw new Error("useTheme must be used within ThemeProvider");
  return context;
}
```

### React Navigation — type-safe routes

```tsx
type RootStackParamList = {
  Home: undefined;
  Profile: { userId: string };
  Settings: undefined;
};

const Stack = createStackNavigator<RootStackParamList>();

function ProfileScreen({ route, navigation }: StackScreenProps<RootStackParamList, "Profile">) {
  const { userId } = route.params; // TypeScript knows userId is string
  navigation.navigate("Home"); // navigation is typed too
}
```

### Compound components with generics

```tsx
interface SelectContextValue<T> { value: T; onChange: (value: T) => void; disabled?: boolean; }
const SelectContext = createContext<SelectContextValue<any> | null>(null);

function Select<T>({ value, onChange, children, disabled }: SelectProps<T>) {
  return (
    <SelectContext.Provider value={{ value, onChange, disabled }}>
      <View>{children}</View>
    </SelectContext.Provider>
  );
}

function SelectOption<T>({ value, children }: SelectOptionProps<T>) {
  const context = useContext(SelectContext);
  if (!context) throw new Error("SelectOption must be within Select");
  const isSelected = context.value === value;
  return <TouchableOpacity onPress={() => context.onChange(value)}>{children}</TouchableOpacity>;
}
```

## Best Practices & Patterns

### Strict mode — the single biggest quality boost

Enable `"strict": true` in `tsconfig.json`:

```json
{
  "compilerOptions": {
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,
    "noImplicitReturns": true,
    "noFallthroughCasesInSwitch": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true
  }
}
```

| Flag | Catches |
|------|---------|
| `noImplicitAny` | Variables without explicit types |
| `strictNullChecks` | `null`/`undefined` not handled |
| `strictFunctionTypes` | Contravariant parameter checking |
| `strictPropertyInitialization` | Uninitialized class properties |

<Callout variant="warning">
**Never disable `strictNullChecks`**. It forces you to handle `null`/`undefined` explicitly, eliminating a huge class of runtime errors.
</Callout>

### Branded types — domain modeling

```ts
type Brand<T, B> = T & { __brand: B };
type UserId = Brand<string, "UserId">;
type PostId = Brand<string, "PostId">;
type Email = Brand<string, "Email">;

function createUserId(id: string): UserId { return id as UserId; }
function createEmail(email: string): Email {
  if (!email.includes("@")) throw new Error("Invalid email");
  return email as Email;
}

function getUser(id: UserId) { /* ... */ }
getUser(userId);    // OK
// getUser(postId); // Error!
```

### Discriminated unions — modeling state machines

```ts
type ApiState<T> =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; data: T }
  | { status: "error"; error: Error; retry: () => void };

function handleState<T>(state: ApiState<T>) {
  switch (state.status) {
    case "idle": return "Ready";
    case "loading": return "Loading";
    case "success": return `Got ${JSON.stringify(state.data)}`;
    case "error": return `Error: ${state.error.message}`;
  }
}
```

### Architectural patterns

**Repository pattern with generics:**

```tsx
interface Repository<T, ID> {
  findById(id: ID): Promise<T | null>;
  findAll(): Promise<T[]>;
  create(entity: T): Promise<T>;
  update(id: ID, entity: Partial<T>): Promise<T>;
  delete(id: ID): Promise<void>;
}

class HttpRepository<T, ID> implements Repository<T, ID> {
  constructor(private baseUrl: string, private idKey: keyof T) {}
  async findById(id: ID): Promise<T | null> {
    const res = await fetch(`${this.baseUrl}/${id}`);
    return res.ok ? res.json() : null;
  }
  // ... other methods
}
```

**Factory pattern with type safety:**

```tsx
type NotificationType = "email" | "push" | "sms";
const factories: Record<NotificationType, () => Notification> = {
  email: () => new EmailNotification(),
  push: () => new PushNotification(),
  sms: () => new SMSNotification(),
};
function createNotification(type: NotificationType): Notification { return factories[type](); }
```

### Anti-patterns to avoid

| Anti-Pattern | Better Approach |
|--------------|-----------------|
| `any` everywhere | Use `unknown`, generics, or proper types |
| `// @ts-ignore` | Fix the underlying type issue |
| `as SomeType` assertions | Narrow with guards, refine types |
| Giant interfaces | Split into smaller, composable types |

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "jsx": "react-jsx",
```

### JS → TypeScript migration

**Phase 1: Setup without breaking**

```bash
npm install -D typescript @types/node @types/react @types/react-dom
```

**Phase 2: Rename files incrementally** — one file at a time, fix errors, commit, test, repeat.

**Phase 3: Enable strict gradually**

```json
{
  "compilerOptions": {
    "strict": false,
    "noImplicitAny": true,
    "strictNullChecks": true,
    "strictFunctionTypes": true
  }
}
```

**Phase 4: Add types to dependencies**

```ts
// For packages without types
declare module "untyped-package" {
  export function doThing(options: { foo: string }): Promise<string>;
}
```

**Phase 5: Migrate config files** — `vite.config.js` → `vite.config.ts`, etc.

### Common production issues

- **"Cannot find module" with path aliases** — ensure `tsconfig.json` paths match your bundler config
- **Types work in IDE but fail in CI** — lock `typescript` version, align `@types/*` packages
